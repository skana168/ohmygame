# Domain docs

This repository uses a single-context layout: root `GLOSSARY.md`
and `docs/adr/`.

## Before exploring

- Read `GLOSSARY.md` for shared domain vocabulary.
- Read ADRs in `docs/adr/` that concern the area being explored.

If these documents are absent, proceed silently. The domain-modeling
skill creates them when terms or decisions are resolved.

## Use the glossary’s vocabulary

Use defined terms in issue titles, proposals, hypotheses, and test names.
Follow any guidance about synonyms to avoid.

If a needed concept is missing, reconsider whether it belongs in the
project’s vocabulary or note the gap for domain-modeling.

## Surface ADR conflicts

When a proposal contradicts an existing ADR, identify the ADR and explain
why its decision should be reconsidered.
